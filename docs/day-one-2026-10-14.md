## 2. The 7 bugs, and what each one actually was

Five of the seven are in `carrier.rs`. **All five have the same shape: the code claimed to model phase and then discarded it.**

| # | file | what was wrong | cost of leaving it |
|---|---|---|---|
| 1 | `ladder.rs` | named arguments (`gain: 1.0`) — Rust has never had them | suite never compiled |
| 2 | `ladder.rs` | `reach()` clamped the **shift amount** not the result, so W32/W64/W128/W256 **all returned 65536** | top four rungs of the ladder had identical authority — a ladder that isn't a ladder |
| 3 | `ladder.rs` | test assumed the sequence 1,2,4; actual is 1,4,8,… | test was wrong, not code |
| 4 | `carrier.rs` | `notch_db()` returned `20*log10(null/peak)` — **negative for every channel that has a notch** — then compared `notch < 3.0` | **the gate was inverted.** refused the deep (correctable) nulls, accepted flat ones. The proposition the file exists to state was testing backwards |
| 5 | `carrier.rs` | `two_path_channel()` used `-0.4`; a two-path response only nulls when the reflection is at least as strong as the direct path (at `-0.4`, best notch 7.4 dB) | the file's own test asserted `> 10 dB`. **the assertion was right and the fixture was wrong** |
| 6 | `carrier.rs` | `equalise()` hardcoded `yi = 0.0` | **the real one.** returned `cos(phi)` — measured **0.9938837** where 1.0 was asked. `equalise()` now takes `&[(f64,f64)]` |
| 7 | `carrier.rs` | noise-floor gate: `notch < |noise_floor|` was the **refusal** condition | refused correctable frames (20.3 dB notch / 80 dB headroom), equalised hopeless ones. correct form: `notch_depth < noise_headroom` |

### The one that matters most

Bug 4 is the worst of the seven and not because it is subtle.

The entire interstalk thesis — papers 24 and 25, the uncorrectable-clean-channel property — reduces to one function. That function had an inverted comparison, so for the core's entire existence it had been **refusing exactly the channels it was built to accept.** The test that guards it (`clean_channel_is_uncorrectable`) passed anyway, because a clean channel is refused under either sign. **The guard test could not see the bug it was guarding.** That is a finding worth more than the fix.

### The discipline that produced this

- every bug was diagnosed from the failing output before being changed
- no tolerance was loosened to make anything pass. the one threshold (`1e-6`) is *tighter* than the original `1e-9`, because the recovered value is now exact rather than approximately right
- one intermediate attempt was wrong (`imag_at(f) * rx[k]`, which produced 1.0159) and was reverted rather than iterated on. the mistake was diagnosed: the formula had never been wrong, the **input** was. the fix was to pass a complex frame
- CENTRAL-RULES §1 and §4 both earned their place. §4 is "surprising result = suspect my code first" — the six failures were surprising, and all six were my code

## 4. The comparison Bobby asked about, recorded

*"interesting llm is considered a transformer architecture but it seems to me we have the real deal as a stalk transformer architecture"*

| | LLM transformer | this core |
|---|---|---|
| tokens | learned embeddings | fixed base point, fixed distance |
| attention | learned weights | `Channel` taps — structural, measured |
| layer norm | learned scale/shift | `Envelope` D1-D4, declared at construction |
| scope | one thing it does | one thing it does |

The last row is the whole argument. A transformer generalises because nothing is pinned; this core is 1796 lines because **every number in it is pinned.**

But the real difference is not the pinning. It is **where the transformation happens.**

An LLM transformer transforms *content*: token → vector → attention → logits. The meaning moves; the channel is never stated.

**This one transforms interference, and the interference is the structure.** `K_ij` is not a learned weight — it is a measurement of what is physically coupling two stalks. `Channel::notch_db()` is a dB reading, not a parameter. `EqualiseError::FlatChannel` is a receiver refusing a frame it cannot equalise.

> an LLM transformer transforms meaning and leaves its channel unstated. this one transforms a stated channel and leaves the meaning alone.

That is why this is a **governor** and an LLM is not. Refusing requires knowing what you refused *out of*.

And the 3-part stalk (v6.2) is where this stops being a parallel: **2 loop modes per stalk instead of 1**, on a core that does not want degeneracy. An LLM needs 20 distinct axes to come out of training data. Changing a winding ratio produced them.

## 5. What I like, and what I do not

**Do not touch — the best thing in the codebase.** `lib.rs`:

> It is not a model, not an orchestrator, and not aware of what it is governing. That blindness is the design.

with the 747 argument: *a veto the governed process can decline to call is not a veto.* That blindness is **why the core is small enough to trust**, and it is why one thing can govern coding, robot, language and self while knowing none of them. 1796 lines is the size of a core that refuses to understand what it governs.

**Also good, and now verified:** fail-closed stickiness, the named-refusal triple (`FlatChannel` / `AxisBelowFloor(&'static str)` / `Refusal::Stale{..}`), and the zero-dependency constraint — a governor that pulls in a serialization stack has its supply chain inside the trust boundary.

**Not good, and open:** `sheaf.rs` puts `star_floor: 50` on the admission path. That contradicts a decision already on record — the integration registry (2026-10-09): *"openclaw 391k stars MIT yet reference-only — stars must never promote into the runtime path."* `admit()` would wave it through. A system whose thesis is *don't let a proxy stand in for the thing* has a proxy sitting on its admission gate.

**Also still missing:** MLTR (the largest of the 4 sheafs does not exist in any repo); a coding client (the gate exists and nothing pulls); a real corpus through MTE (P5/T5 unmeasured).
