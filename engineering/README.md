# engineering/

**Filed:** 2026-09-13 by Hermes for Bobby.

**Status:** empty placeholder. Reserved for engineering artifacts (design docs, build plans, integration specs, deployment guides) that don't fit cleanly into `docs/` (math) or `src/` (code).

## What goes here (when populated)

- Cross-cutting engineering specs (multi-component build plans)
- Integration specs (how fieldcore + simself compose)
- Hardware/software interface contracts
- Build pipeline documentation
- Performance budgets + benchmarks
- Deployment guides (when not just simself)

## What does NOT go here

- Pure math (→ `docs/Math/`)
- Pure code (→ `src/`)
- Architecture theory (→ `docs/` root or `docs/Math/`)
- Identity-layer docs (→ `simself/docs/`)

## Conventions

- Markdown only.
- Each engineering doc has a **what**, **why**, **how** structure.
- Each engineering doc references the canonical math it relies on (with `docs/Math/<file>.md` links).
- Diagrams in Mermaid or ASCII (no binary files).
